# 안전보건 정보 모니터링 v2

> 이름은 법령·고시 개정 추적에 더해 KOSHA 가이드, 안전보건 뉴스, 사규 개정 연계까지 아우르도록 예전의 "안전보건 법령·고시 Monitoring"에서 바꾼 것입니다.

회사가 보유한 안전보건 절차서/지침서/작업표준의 근거가 되는 대한민국 법령(법률·시행령·시행규칙)과
행정규칙(고시·예규·훈령)의 개정 여부를 자동으로 추적하고, 어떤 회사 문서가 영향을 받는지 한눈에
파악할 수 있는 웹 대시보드입니다.

> **v2 안내**: 이 저장소는 기존 `Safety-Law-Monitoring-Sys` 저장소(법령·고시 개정 추적 핵심/확장
> 기능 전체)를 그대로 옮긴 뒤, **대시보드 안전보건 뉴스 자동 스크롤 게시판** 기능을 새로 추가한
> 버전입니다. 기존 저장소는 그대로 보존되며, 이후 개발은 이 v2 저장소를 기준으로 이어갑니다.
> 새로 추가된 기능은 아래 "0. 안전보건 뉴스 자동 스크롤 게시판" 항목을 참고하세요.

## 왜 필요한가

- 안전보건 관련 법령·고시가 워낙 많고 자주 개정되어 매일 수작업으로 조회하기엔 시간이 많이 듭니다.
- 이 프로그램은 **추적하고 싶은 법령/고시를 등록**해두면, 주기적으로 국가법령정보센터 Open API를
  조회해 공포일자/공포번호/시행일자가 바뀌었는지 자동으로 비교하고, 바뀐 건만 "개정 이력"으로
  쌓아줍니다.
- 회사의 절차서/지침서/작업표준을 법령과 **수동으로 매핑**해두면, 특정 법령이 개정될 때 어떤 문서를
  검토해야 하는지 자동으로 보여줍니다(대시보드).

## 핵심 기능 vs 확장 기능

이 프로그램의 우선순위는 명확히 2단계로 나뉩니다.

- **핵심 기능 (반드시 필요)**: 국가법령정보센터에서 산업안전보건 관련 법이 재개정됐을 때 모든 것을
  일일이 확인하기는 어려우니, 자주 보는 법률을 **법령 마스터**에 등록해두고 그 법률들의 재개정
  이력을 **한 곳에서 한 번에** 확인하는 것. (아래 1~3번)
- **확장 기능 (핵심이 안정화된 뒤 점진적으로 확장)**: 회사가 쓰는 절차서/지침서 내용을 등록하고,
  법령이 재개정됐을 때 그 절차서/지침서가 업데이트되어야 하는지를 자동으로 모니터링·알람하는 것.
  (아래 4~6번)

대시보드도 이 구분을 그대로 반영해 **"법령 개정 리스트"**(핵심 - 등록된 모든 법령의 개정을 보여줌)와
**"사내 절차서·지침서 개정 필요 사항"**(확장 - 문서와 매핑된 법령의 개정만 추려서 보여줌) 두 영역으로
나뉘어 있습니다.

0. **안전보건 뉴스 자동 스크롤 게시판 (v2 신규)**: 고용노동부·안전보건공단 안전보건 이슈, 중대재해
   관련 뉴스를 대시보드 상단에 게시판처럼 자동으로 스크롤해서 보여줍니다. RSS/Atom 피드를 주기적으로
   읽어와 채우며, 항목을 클릭하면 원문으로 이동합니다. 자세한 내용은 아래
   "안전보건 뉴스 자동 스크롤 게시판" 절 참고.
1. **법령 마스터 관리**: 법령명으로 검색해 추적 목록에 등록/제거 (핵심)
2. **자동 개정 감지**: "새로고침" 버튼 또는 자동 스케줄러/크론으로 공포일자·시행일자 변경 감지 (핵심)
3. **개정 이력 관리**: 감지된 개정 건을 미검토 → 검토중 → 반영완료 상태로 추적 (핵심)
3-1. **신규 제정 고시 자동 탐지**: 고시는 기존 것이 "개정"되는 게 아니라 매년 새로 "제정"되는
   경우가 많아, 등록해둔 항목의 변경만 감지하는 2번만으로는 놓칠 수 있습니다. "새로고침"을 누를
   때마다 **소관부처**가 설정에 지정한 부처와 일치하면서 이름에 **키워드** 중 하나라도 포함된, 아직
   등록 안 한 고시·예규·훈령을 찾아 대시보드에 후보로 보여줍니다(부처 AND 키워드, 이중 필터).
   기준은 설정 탭 "신규 제정 고시 자동 탐지"에서 바꿀 수 있습니다. (핵심)
4. **회사 문서 관리**: 절차서/지침서/작업표준을 문서번호, 개정번호 등과 함께 등록 (확장)
5. **문서-법령 매핑**: 회사 문서를 등록/수정할 때 근거 법령·고시를 함께 체크해 연결 → 개정 시 자동 알림 대상 산출 (확장)
5-1. **키워드(해시태그) 자동 매칭**: 문서에 "#밀폐공간 #공기호흡기"처럼 키워드를 등록해두면, 근거
   법령으로 직접 매핑하지 않았더라도 그 키워드가 이름/본문에 들어간 법령·고시가 개정될 때만 자동으로
   "개정 필요 사항"에 표시됩니다(`#태그매칭` 배지로 구분). 본문 매칭은 아래 본문 캐시가 있어야 동작하며,
   추적 중인 법령의 본문은 동기화할 때마다 자동으로 갱신됩니다. (확장)
6. **법령 본문검색**: 국가법령정보센터 API는 법령명 검색만 지원하고 전체 법령 대상 본문검색은
   제공하지 않으므로, 설정 탭의 "법령 본문 캐시"에 미리 받아둔 본문을 대상으로 검색합니다. "법령
   마스터" 탭 검색창의 "본문검색" 토글을 켜면 법령명이 아니라 본문 내용으로 찾습니다. (확장)
7. **KOSHA 가이드**: 한국산업안전보건공단(KOSHA)이 발간하는 기술지침(KOSHA GUIDE)을 등록해서
   관리하는 "개정 이력" 옆의 별도 탭입니다. 공공데이터포털의 "기술지원규정(코샤가이드) 조회서비스"
   Open API로 지침번호·명칭·공표일자·원문 다운로드 링크를 포함한 전체 목록을 한 번에 동기화하거나,
   한 건씩 입력, 또는 갖고 있는 목록을 붙여넣기(일괄 등록)로 채울 수도 있습니다. 등록해두면
   지침번호·제목·본문(입력한 경우)을 대상으로 하는 키워드 검색이 그 안에서 바로 동작합니다. API가
   원문 링크를 못 채워오는 항목이 있으면, 가이드 "수정"에서 PDF 파일을 직접 첨부할 수도 있습니다
   (서버 로컬 폴더에만 저장되고 외부로 전송되지 않습니다). (확장)

## 기술 스택

- 백엔드: Python + FastAPI + SQLAlchemy (SQLite)
- 프론트엔드: 별도 빌드 과정 없는 순수 HTML/CSS/JS (백엔드가 정적 파일로 서빙)
- 데이터 소스: [국가법령정보센터 Open API](https://open.law.go.kr) (`target=law` 법령, `target=admrul` 행정규칙/고시)

## 시작하기

### 1) 국가법령정보센터 Open API 키(OC) 발급 (선택, 권장)

1. https://open.law.go.kr 회원가입
2. 마이페이지 > 오픈API 신청 (사용자 인증키(OC) 발급, 승인까지 1~2일 소요될 수 있음)
3. 발급받은 OC 값을 `.env`의 `LAW_API_OC`에 넣거나, 대시보드의 **설정** 탭에서 입력

> OC 키가 없어도 **데모 모드**로 샘플 법령/고시 데이터를 이용해 화면 전체를 미리 확인할 수 있습니다.

> 사내 부서원 배포판(설치 파일)은 배포 담당자가 OC 키·KOSHA 가이드 인증키를 DB에 미리 설정해서 만들기 때문에,
> 사용자용 문서(도움말, 설치안내)에는 인증키 발급·입력 절차를 넣지 않았습니다.

### 2) 백엔드 설치 및 실행

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env         # 필요시 LAW_API_OC 등 입력
uvicorn app.main:app --reload --port 8000
```

브라우저에서 http://localhost:8000 접속 → 대시보드가 뜹니다. (프론트엔드는 백엔드가 정적 파일로 함께 서빙합니다)

### 2-1) 다음부터 재시작할 때 (Windows)

최초 설치가 끝난 뒤에는 컴퓨터를 껐다 켜거나 PowerShell을 새로 열 때마다 매번 `git pull` +
가상환경 활성화 + `uvicorn` 실행 명령을 따로따로 칠 필요 없이, 프로젝트 루트의 `run.bat`
파일을 **탐색기에서 더블클릭**하면 한 번에 처리됩니다.

더블클릭하면 원래 열렸던 cmd 창은 바로 사라지고, 대신 `run.ps1`이 실행되는 새 PowerShell
창이 뜹니다(cmd 창이 그대로 남아서 서버를 직접 실행하면, 나중에 Ctrl+C를 눌렀을 때
cmd.exe가 자체적으로 "Terminate batch job (Y/N)?"을 물어보며 창이 통째로 닫혀버리는
문제가 있어서 이렇게 분리했습니다). **앞으로는 이 새로 뜬 PowerShell 창을 계속 쓰면
됩니다.**

이 방법은 PowerShell의 "스크립트 실행 정책"을 계정이나 시스템에 영구적으로 바꾸지
**않습니다.** `run.bat`이 새로 띄우는 PowerShell 창 한 개에만 실행 허용이 임시로
적용되고, 그 창을 닫으면 사라지는 방식이라 회사 컴퓨터의 보안 정책과 충돌하지
않습니다. (원리: `run.bat` 안에서 `powershell.exe -ExecutionPolicy Bypass -File run.ps1`
형태로 실행하는데, 이 `-ExecutionPolicy Bypass`는 그 순간 새로 켜는 PowerShell
프로세스 하나에만 적용되는 명령줄 옵션이지, `Set-ExecutionPolicy`처럼 레지스트리에
저장되는 영구 설정이 아닙니다.)

PowerShell 창에서 직접 실행하고 싶다면 이렇게 해도 됩니다 (이 경우 앞에서 안내한
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`를 그 창에서 한 번
먼저 실행해야 함 - 마찬가지로 그 창에만 적용되고 영구 변경은 아님):

```powershell
cd "본인의 프로젝트 폴더 경로\Safety-Law-Monitoring-Sys"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\run.ps1
```

코드를 수정한 뒤 새로고침하고 싶을 때는 창을 닫지 않고 **Ctrl+C**로 서버만 멈추면 됩니다.
그러면 `run(또는 start)을 입력하세요` 프롬프트가 뜨는데, 여기에 `run`(또는 `start`)을 입력하면
같은 창에서 `git pull`부터 다시 실행합니다. 완전히 끝내려면 `exit`을 입력하세요.

이 스크립트가 자동으로 `git pull` → 가상환경 활성화 → 서버 실행까지 순서대로 해줍니다.

### 3) 사용 순서

1. **법령 마스터** 탭에서 `산업안전보건법`, `산업안전보건기준에 관한 규칙` 등으로 검색 후 등록
2. **회사 문서** 탭에서 보유한 절차서/지침서/작업표준을 등록하면서, "근거 법령" 체크박스에서 관련
   법령·고시를 함께 선택 (나중에 문서를 수정할 때 다시 바꿀 수 있습니다)
3. 상단의 **지금 동기화**를 눌러 최신 상태를 확인 (최초 동기화는 기준값만 저장하고, 이후 값이 바뀌면 "개정 이력"에 기록됩니다)

## 안전보건 뉴스 자동 스크롤 게시판 (v2 신규)

대시보드 상단(요약 카드 바로 아래)에 고용노동부/안전보건공단 안전보건 이슈, 중대재해 관련 뉴스를
게시판처럼 자동으로 스크롤해서 보여줍니다.

- 3개 카테고리(고용노동부/안전보건공단/중대재해 뉴스)별로 RSS 또는 Atom 피드 주소를 설정 탭
  **"안전보건 뉴스 게시판"**에서 지정하면, 서버가 주기적으로(기본 3시간, `.env`의
  `NEWS_FETCH_INTERVAL_HOURS`) 읽어와 새 항목만 저장합니다. "지금 새로고침" 버튼으로 즉시 가져올
  수도 있습니다.
- **기본 피드 주소는 구글 뉴스 검색 RSS(`news.google.com/rss/search`)로 채워져 있습니다.** 이
  프로젝트를 만드는 환경에서는 `moel.go.kr`/`kosha.or.kr`에 대한 네트워크 접근이 막혀 있어(국가법령정보센터와
  같은 사정, 아래 절 참고) 두 기관의 공식 RSS 주소를 실제로 검증하지 못했습니다. 공식 RSS 주소를
  확인하면 설정 탭에서 그 주소로 바꿔 끼우세요 (표준 RSS 2.0 또는 Atom 형식이면 어떤 URL이든 동작).
- 피드를 아직 못 가져왔거나(네트워크 차단, 주소 미설정 등) 새로 배포한 직후라 게시판이 비어 보이지
  않도록, 그동안은 예시(데모) 데이터로 채워지고 대시보드에 **"예시 데이터"** 배지가 함께 표시됩니다.
  실제 데이터가 들어오기 시작하면 예시 항목은 자동으로 정리됩니다.
- 상단 필터(전체/고용노동부/안전보건공단/중대재해 뉴스)로 좁혀볼 수 있고, 항목을 클릭하면 새 탭으로
  원문이 열립니다. 마우스를 올리면 자동 스크롤이 멈춥니다.
- 설정 탭에서 게시판 표시 여부, 보관 기간을 함께 조절할 수 있습니다.
- **보관 정책**: 뉴스 1건은 URL/제목 정도라 용량이 작지만(건당 1KB 미만) 무한정 쌓아둘 필요는 없어,
  발행일(`published_at`, 없으면 `fetched_at`) 기준 **보관 기간**(설정 탭 `.env`의 `NEWS_RETENTION_DAYS`,
  기본 180일 = 6개월)이 지나면 자동 삭제됩니다. 계속 남겨두고 싶은 기사는 "안전보건 뉴스" 탭에서
  **"보관"** 처리해두면(`NewsItem.is_archived`) 기간이 지나도 삭제되지 않고, "보관함만 보기"로 모아볼
  수 있습니다. (혹시 모를 피드 오설정으로 한 카테고리에 비정상적으로 많이 쌓이는 경우에 대비해, 보관
  처리 안 된 항목은 카테고리당 5,000건을 넘으면 오래된 것부터 정리되는 안전장치도 있습니다.)
- **안전보건 뉴스 탭(별도 페이지)**: 대시보드와 법령 마스터 사이에 있는 전용 탭(또는 게시판의
  "전체보기 · 검색" 버튼)에서 카테고리·제목 키워드·날짜 범위(시작일/종료일)로 뉴스를 검색하고,
  각 항목을 보관/보관 해제할 수 있습니다. 검색 가능한 기간은 위 보관 기간만큼으로 한정됩니다 -
  더 오래된 기사까지 찾으려면 그 값을 늘려두세요.

## 국가법령정보센터 API 응답 필드 확인 방법 (중요)

이 프로젝트를 만드는 환경에서는 open.law.go.kr에 대한 네트워크 접근이 막혀있어, `app/law_api.py`의
XML 필드 매핑(`_FIELD_CANDIDATES`)은 공식 문서상 널리 알려진 필드명을 기준으로 작성했지만 **실제 응답으로
검증하지는 못했습니다**. OC 키를 발급받은 뒤 아래처럼 직접 한 번 호출해 실제 태그명을 확인하고,
필요하면 `_FIELD_CANDIDATES`에 후보 태그명을 추가해주세요.

```bash
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=발급받은OC값&target=law&type=XML&query=산업안전보건법"
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=발급받은OC값&target=admrul&type=XML&query=위험성평가"
```
